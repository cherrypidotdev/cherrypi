# Плагины

Плагин — это **песочный Lua-бандл**, установленный на уровне agency. Это не
демон: agency вызывает его как обработчик запроса, вызов выполняется до конца, а
необходимое состояние живёт в собственной базе плагина.

Плагины — это способ подключить интеграцию к CherryPi, не форкая agency: вебхук
провайдера создаёт задачу, задача получает инструмент провайдера, или событие
задачи доставляется в чат-сервис.

::: tip
Agency исполняет Lua-код; вы поставляете только текстовые файлы. Никакого
компилятора, WASM-тулчейна и sidecar-процесса.
:::

## Что умеет плагин

| Обработчик | Вызывается, когда | Типичное применение |
| --- | --- | --- |
| `handle_http_request` | Приходит запрос на `/plugins/<id>/…` | Вебхук провайдера, OAuth-callback |
| `handle_tool_call` | Агент вызывает инструмент, прикреплённый плагином к задаче | Одобрить merge request, ответить в треде |
| `handle_event` | Agency испускает событие, на которое подписан плагин | Уведомить пользователя, что задаче нужен ввод |
| `handle_tick` | Срабатывает расписание из манифеста, пока плагин включён | Опрашивать провайдера, который не умеет присылать вебхуки |

Плагин также может обращаться к agency: читать проект или задачу, создавать
задачу с промптом и инструментами, читать собственные настройки.

## Установка

1. Заархивируйте **содержимое** бандла — `plugin.json`, Lua-файлы и
   необязательные `migrations/` — а не саму директорию:

   ```sh
   cd my-plugin
   zip -r ../my-plugin.zip .
   ```

2. Откройте **Organization settings → Plugins** и загрузите zip.
3. Установка включает **организационные** настройки плагина и создаёт его
   актора (`@plugin-<id>`).

Повторная установка того же id обновляет плагин и сохраняет его состояние
включённости. Отключение останавливает все обработчики; удаление убирает код и
сохраняет данные, если не запрошено полное удаление.

## Поверхности настроек

Плагин объявляет нужные поверхности в манифесте. Каждая поверхность хранит свои
JSON-значения и имеет собственное правило включения:

| Поверхность | Кто включает | Где редактируется |
| --- | --- | --- |
| `org` | Установка плагина | Organization settings → Plugins |
| `project` | Владелец проекта приглашает актора плагина, затем включает | Project settings → Plugins |
| `agent` | Владелец агента включает | Agent settings → Plugins |
| `user` | Пользователь включает | User settings → Plugins |

Поверхность проекта также несёт два принудительных переключателя agency:

- **Разрешить создание задач** — если выключено, `create_task` завершается
  ошибкой, даже когда плагин включён;
- **Максимальный приоритет задачи** — по умолчанию medium, чтобы плагин не мог
  незаметно создавать critical-задачи.

Поверхность, которая не хранит собственных значений, объявляется пустой картой
`properties`. Так плагин просит владельцев проекта установить и включить его без
настроек уровня проекта:

```json
"settings": { "project": { "type": "object", "properties": {} } }
```

Такая поверхность по-прежнему показывает принудительные переключатели agency и
логи выполнения, а вместо формы настроек сообщает, что форма не объявлена.

Поверхность без ключа `properties` вообще (`{"type":"object"}` или
`{"type":"object","additionalProperties":true}`) — обратный случай: у неё
остаётся свободный JSON-редактор для значений, форму которых плагин не
объявляет. Объявляйте поля в `properties`, когда плагин их знает: именно это
даёт типизированную форму, заголовки и маскирование секретов.

Актор плагина должен быть участником проекта с доступом member, прежде чем
поверхность проекта можно будет включить. Пригласите его из **Project settings →
Access** или из панели плагина.

::: warning Секреты
Свойство настроек с `"format": "password"` (или `"secret": true`) доступно
только для записи. Agency скрывает его в ответах, а пустое значение при
сохранении оставляет прежнее.
:::

### Подсказки по настройке

Поверхность может нести руководство по настройке рядом со своими полями. Оно
рендерится как сворачиваемый блок **Setup** над формой, тем же Markdown, что и
остальной интерфейс (таблицы, ссылки, код и очищенный HTML). Это текст
манифеста, который проверяют при установке, а не состояние времени выполнения:

```json
"settings": {
  "project": {
    "type": "object",
    "setup": {
      "title": "Webhook setup",
      "markdown": "Создайте вебхук на `{{ pluginUrl }}/webhook`."
    },
    "properties": { "...": {} }
  }
}
```

`setup` может быть и просто строкой Markdown; тогда заголовок — `Setup`.
Agency подставляет эти общеизвестные значения, когда отдаёт форму:

| Токен | Значение |
| --- | --- |
| `{{ agencyUrl }}` | Внешний адрес agency (`CHERRYPI_PUBLIC_URL`), без завершающего слэша. |
| `{{ pluginId }}` | Id плагина, например `gitea-reviewer`. |
| `{{ pluginName }}` | Отображаемое имя плагина. |
| `{{ pluginUrl }}` | `{{ agencyUrl }}/plugins/{{ pluginId }}`. |
| `{{ scope }}` | Редактируемая поверхность: `org`, `project`, `agent` или `user`. |
| `{{ targetId }}` | Цель поверхности (id проекта или актора; пусто для `org`). |

Работают обе формы — `{{ token }}` и `{{token}}`; неизвестный токен остаётся
как написан. Бандл, объявляющий `setup`, должен требовать plugin API
`>=0.2.4 <0.3.0`.

### Шаблонные настройки

Строковое свойство с `"format": "template"` — это редактируемый Jinja-промпт.
Карта `x-template.variables` объявляет именованные переменные, их описания и
примеры значений для предпросмотра в форме:

```json
"incident_prompt": {
  "type": "string",
  "format": "template",
  "title": "Incident prompt",
  "default": "Инцидент в #{{ channel.name }}: {{ incident.text }}",
  "x-template": {
    "variables": {
      "channel.name": {
        "type": "string",
        "description": "Имя канала без ведущего #.",
        "sample": "ops"
      }
    }
  }
}
```

Пустое значение наследует `default` из манифеста. Agency проверяет default при
установке и каждое сохраняемое значение: компилирует Jinja, проверяет, что все
используемые переменные объявлены, и делает пробный рендер с примерами. Форма
показывает предпросмотр через **PreviewPluginTemplate**, поэтому браузер не
повторяет движок. Синтаксис — тот же ограниченный Jinja, что у шаблонов задач:
strict undefined, без include, макросов, импортов и наследования, с лимитами на
размер исходника и результата.

Плагин рендерит сохранённый шаблон во время выполнения через
`cherrypi.template.render(source, vars)`. Метод бросает ошибку; оберните его в
`pcall`, чтобы вернуться к значению по умолчанию.

Поля можно складывать в сворачиваемые группы через `x-groups`:

```json
"x-groups": [
  {
    "id": "instructions",
    "title": "Instructions & templates",
    "fields": ["incident_prompt"]
  }
]
```

Поле может входить не более чем в одну группу; неизвестное поле — ошибка
установки. Поля вне групп попадают в группу **Other**. Группы всегда
открываются свёрнутыми.

## Написание плагина

### Манифест

```json
{
  "id": "acme-git-reviewer",
  "name": "AcmeGit Reviewer",
  "version": "0.1.0",
  "requires_agency": ">=0.2.2 <0.3.0",
  "description": "Turns review events into review tasks.",
  "runtime": "lua",
  "entry": "main.lua",
  "handlers": ["http", "tool"],
  "settings": {
    "org": {
      "type": "object",
      "properties": {
        "base_url": { "type": "string", "title": "Git base URL" },
        "api_key": { "type": "string", "format": "password" }
      }
    },
    "project": {
      "type": "object",
      "setup": {
        "title": "Webhook setup",
        "markdown": "Create a webhook at `{{ pluginUrl }}/webhook`."
      },
      "properties": {
        "git_project_id": { "type": "string" },
        "webhook_secret": { "type": "string", "format": "password" }
      }
    }
  },
  "tools": [
    {
      "name": "approve_mr",
      "description": "Approve the merge request under review.",
      "input_schema": {
        "type": "object",
        "required": ["approve"],
        "properties": { "approve": { "type": "boolean" } }
      }
    }
  ],
  "events": ["task_settled"],
  "network": ["git.example.com"],
  "routes": [{ "path": "/webhook", "methods": ["POST"] }],
  "limits": { "timeout_seconds": 10, "max_concurrent": 2 }
}
```

| Поле | Значение |
| --- | --- |
| `id` | Lowercase-slug, 2–48 символов. Становится `/plugins/<id>/` и `@plugin-<id>`. |
| `requires_agency` | Semver-диапазон plugin API, который поддерживает бандл. Пустой — любой. |
| `handlers` | `http`, `tool`, `event`, `tick` и необязательный хук `task_tools`. Первые четыре выводятся из `tools`, `events` и `schedule`, если не указаны; `task_tools` всегда объявляется явно. |
| `settings` | JSON-схемы поверхностей с необязательным Markdown-блоком `setup`. Рендерятся и читаются только объявленные поверхности. |
| `tools` | Именованные инструменты, которые плагин может прикрепить к задаче. |
| `schedule` | Необязательный периодический триггер для `handle_tick`: `{ "every_seconds": 5…3600 }`. См. [Запланированные тики](#запланированные-тики). |
| `events` | События agency, которые получает `handle_event`. |
| `network` | Allowlist исходящих хостов: точный хост, поддомен-шаблон `*.example.com` или `*` для любого хоста. См. [Allowlist сети](#allowlist-сети). |
| `routes` | Документация путей под `/plugins/<id>/`; для диспетчеризации не нужна. |
| `limits` | Уменьшить таймаут, размер ответа/запроса или конкурентность. |

`requires_agency` — диапазон plugin API, который поддерживает бандл. Текущий
API — `0.2.7`: он добавил событие `task_input_answered` поверх
`cherrypi.respond_task_input` и полей диалога в `task_requested_input` из
`0.2.6`, шаблонных настроек, `x-groups` и
`cherrypi.template.render(source, vars)` из `0.2.5`, необязательного блока
`setup` и `get_org().url` из `0.2.4`, обработчика `task_tools` из `0.2.3`, поля
`schedule` и `handle_tick` из `0.2.2` и события `task_hold_released` из `0.2.1`.
Бандл, использующий шаблонные настройки или `x-groups`, объявляет
`>=0.2.5 <0.3.0`; отвечающий на диалог — `>=0.2.6 <0.3.0`; подписанный на
`task_input_answered` — `>=0.2.7 <0.3.0`. Это patch-версии, поэтому бандлы,
уже принимающие линию `0.2.x`, продолжают работать.

### Allowlist сети

`network` — allowlist исходящих хостов. Каждая запись — одно из:

| Запись | Совпадения |
| --- | --- |
| `git.example.com` | Ровно этот хост. Поддомены **не** входят. |
| `*.example.com` | Любой поддомен (`api.example.com`, `a.b.example.com`), но не сам `example.com`. Если плагину нужен и apex, перечислите его отдельно. |
| `*` | Любой хост. |

`*` — широкое явное разрешение: плагин может обращаться к любому публичному
HTTPS-хосту. Это нужно, когда URL провайдера задаётся настройкой оператора,
например self-hosted MatterMost `base_url`. Запись обязана быть единственной в
`network`, отображается предупреждением в панели плагина и заслуживает проверки
манифеста перед установкой. Она не ослабляет HTTPS-правило и защиту agency от
приватных адресов.

### Обработчики

```lua
function handle_http_request(route, headers, body)
  -- route.method, route.path, route.query (таблица массивов)
  -- headers — таблица в нижнем регистре; body — сырое тело запроса.
  if route.method ~= "POST" or route.path ~= "/webhook" then
    return 404, { ["content-type"] = "text/plain" }, "not found"
  end
  local payload = cherrypi.json.decode(body)
  local settings = cherrypi.settings.get("org", "")
  if payload.secret ~= settings.webhook_secret then
    return 401, { ["content-type"] = "application/json" }, '{"error":"bad secret"}'
  end
  local task_id = cherrypi.create_task({
    project = settings.project,
    title = "Review: " .. payload.title,
    prompt = "Review this change:\n" .. payload.text,
    tools = { { name = "approve_mr" } },
  })
  return 200, { ["content-type"] = "application/json" },
    cherrypi.json.encode({ task_id = task_id })
end

function handle_tool_call(task_id, name, args)
  if name ~= "approve_mr" then
    error("unknown tool " .. name)
  end
  local rows = cherrypi.db.query(
    "SELECT mr_iid FROM reviews WHERE task_id = ?", { task_id }
  )
  -- вызовите провайдера через cherrypi.http.request ...
  return "Merge request approved."
end

function handle_event(payload)
  cherrypi.log.info("task " .. payload.task_id .. " is " .. payload.state)
end
```

`handle_http_request` возвращает `(status, headers, body)`. Строковое тело
отправляется как есть; таблица кодируется в JSON. `handle_tool_call` возвращает
текст (таблица кодируется в JSON). `handle_event` ничего не возвращает. Кроме
событий жизненного цикла задачи, `handle_event` получает
`task_input_answered` после ответа на ожидающий диалог — с `request_id`,
`method`, `title`, `message`, читаемым `answer` и атрибуцией `answered_by`.
Неудачный ответ ничего не испускает.

### Запланированные тики

Провайдер, который не умеет присылать входящие события — или чей оператор
отказывается настраивать вебхук — доступен только опросом. Необязательное поле
манифеста `schedule` периодически вызывает `handle_tick`, пока плагин включён:

```json
"schedule": { "every_seconds": 15 }
```

```lua
function handle_tick(now_ms)
  -- now_ms — запланированное время тика в Unix-миллисекундах.
  local cursor = cherrypi.settings.get("org", "").cursor or "0"
  local response = cherrypi.http.request(
    "GET", "https://chat.example.com/api/mentions?since=" .. cursor)
  -- Создайте задачи для новых упоминаний и сохраните новый курсор в БД плагина.
end
```

- `every_seconds` — целое от 5 до 3600; отсутствие `schedule` значит, что плагин
  никогда не тикает. Валидация отвергает значение вне диапазона и расписание у
  бандла, чей entry-файл не определяет `handle_tick`.
- Тикер запускается после установки или включения и при старте agency для
  каждого включённого плагина; выключение и удаление его останавливают. Первый
  тик смещается случайным джиттером меньше интервала, чтобы флот не тикал
  синхронно.
- Тики **single-flight на плагин**: пока один выполняется, следующий интервал
  пропускается и пишется строка `warn`. Тики никогда не встают в очередь.
- Тик, который упал или превысил таймаут, логируется на уровне `error`, а тикер
  сохраняет расписание. Догоняющих тиков после простоя нет: пропущенные
  интервалы пропускаются, а плагин хранит собственный курсор обработанного.
- Тик — обычный вызов: свежий `LState`, слот `max_concurrent`, таймаут
  `timeout_seconds` из манифеста (по умолчанию 10 с), allowlist сети и
  `cherrypi.log.*` с теми поверхностями, которые передаёт плагин.

Эндпоинт вебхука **публичный**: agency не требует сессию, поэтому плагин сам
проверяет секрет. Вызывающий с сессией или personal access token определяется и
доступен как `cherrypi.actor`.

### Проверка настроек

Плагин, который хочет проверять свои настройки, определяет `update_settings`.
Agency вызывает его перед сохранением записи для одной поверхности, с новыми
значениями и сохранёнными:

```lua
function update_settings(scope, target_id, values, previous)
  if scope ~= "project" then return nil end
  local ok, tags = pcall(cherrypi.list_project_tags, target_id)
  if ok and not has_tag(tags, values.tag) then
    return { { path = "tag", errorText = "В проекте нет такого тега." } }
  end
  return nil
end
```

- Верните `nil` или пустой список, чтобы принять запись.
- Верните список `{ path, errorText }`, чтобы **отклонить** её: ничего не
  сохраняется, форма подсвечивает каждое поле с его сообщением, а тост сообщает
  об ошибке.
- Ошибка Lua тоже отклоняет запись — одним сообщением на всю форму.
- Хук выполняется только когда плагин включён, поэтому настройки выключенного
  плагина остаются редактируемыми.

Проверяйте сначала офлайн (форма, допустимые значения) и только потом обращайтесь
к провайдеру: `update_settings`, который ходит в сеть на каждое сохранение,
медленнее формы, которую он обслуживает.

### Фильтр инструментов задачи

Плагин, который объявляет `task_tools` в `handlers`, определяет
`handle_task_tools`. Планировщик вызывает его при старте задачи — после захвата
задачи (claim), когда её исполнитель уже известен, — и спрашивает, какие из
объявленных инструментов проекта этой задаче доступны. `ResolveTool` применяет
тот же фильтр, поэтому скрытый инструмент нельзя вызвать и напрямую.

```lua
function handle_task_tools(task_id)
  local task = cherrypi.get_task(task_id)
  local settings = cherrypi.settings.get("agent", tostring(task.assignee))
  if (settings.api_key or "") == "" then
    return {}
  end
  return { "open_merge_request", "reply_in_discussion" }
end
```

- Верните список имён объявленных инструментов проекта, чтобы сузить задачу до
  них; пустой список скрывает все, а `nil` прикрепляет все объявленные.
- Обработчик никогда не выводится автоматически: плагин без него продолжает
  прикреплять все инструменты проекта, как и раньше.
- Хук, который падает или возвращает не список объявленных инструментов
  проекта, пишет предупреждение и откатывается ко всем объявленным инструментам
  (fail open); `handle_tool_call` всё равно проверяет свои предусловия.
- Инструменты задачи, прикреплённые через `create_task`, не фильтруются: хук
  сужает только инструменты проекта.
- Фильтр вычисляется, когда планировщик создаёт Pi-сессию задачи, — это
  единственный стартовый payload, который несёт инструменты. Задача,
  продолженная на тёплой сессии (settle и следующий follow-up или retry живой
  сессии), сохраняет список инструментов, с которым стартовала, поэтому
  сохранённые посреди задачи учётные данные подействуют только на следующем
  свежем старте.

Так инструмент провайдера, которому нужны учётные данные агента, не попадает в
задачу, где их нет, вместо того чтобы предлагаться и падать при вызове.

### Методы agency

| Метод | Что делает |
| --- | --- |
| `cherrypi.get_org()` | Идентичность agency: `id`, `name` и `url` (публичный адрес без завершающего слэша). |
| `cherrypi.get_project(id_or_slug)` | Метаданные проекта. Нужно членство или включённая поверхность проекта. |
| `cherrypi.get_team(id)` | Метаданные команды. Нужно членство плагина в команде. |
| `cherrypi.get_agent(id_or_actor)` | Метаданные агента. Нужно, чтобы агент или общий проект включил плагин. |
| `cherrypi.get_user(id_or_username)` | Метаданные пользователя. Нужно, чтобы пользователь включил плагин. |
| `cherrypi.get_task(id)` | Снимок задачи. Нужна созданная плагином задача или включённый проект. |
| `cherrypi.get_project_tasks(project_id, opts)` | Задачи проекта (`limit`, `state`, `search`, `archived`). |
| `cherrypi.get_task_history(task_id, opts)` | Сохранённые записи Pi-сессии. |
| `cherrypi.create_task(input)` | Создать задачу в очереди. См. ниже. |
| `cherrypi.hold_task(task_id, hold)` | Удержать задачу, пока плагин не проверит её результат (`key`, `reason`). Идемпотентно по ключу, не более 8 удержаний на задачу. См. [Удержания задач](#удержания-задач). |
| `cherrypi.release_task(task_id, key, options)` | Снять одно удержание. `options.mode` — `settle`, `queue` или `complete`; для `queue` нужен `prompt`. |
| `cherrypi.list_task_holds(task_id)` | Удержания задачи, от старых к новым. |
| `cherrypi.respond_task_input(task_id, request_id, answer)` | Ответить на ожидающий диалог задачи в состоянии `input`: `{ value }`, `{ confirmed }` или `{ cancelled }`. Для пакетной анкеты `value` — это wire JSON расширения (`{"answers":[{"index":0,"options":[1]}]}`, индексы с нуля), а `{ questionnaire = { { question, answer }, ... } }` добавляет пары для resume-промпта. Плагин должен быть лидом задачи; `create_task` делает его лидом. Ответ снимает `input` тем же путём, что и ответ из консоли. |
| `cherrypi.list_agents()` | Агенты, включившие плагин, с их настройками агента. |
| `cherrypi.list_settings(scope)` | Собственные строки настроек плагина для поверхности. |

`create_task` принимает:

```lua
{
  project = "PROJ",              -- id или slug (обязательно)
  title = "Incident: DB down",   -- необязательно; иначе авто-заголовок
  prompt = "Investigate …",      -- обязательно
  tags = { "incident" },         -- имена или id, определённые в проекте
  assignee = "agent-actor-id",   -- агент, являющийся участником проекта
  size = "medium",               -- small | medium | big | epic
  priority = "normal",           -- low | normal | high | critical
  task_references = {            -- informational, если kind = "blocking"
    "PROJ-1",
    { task_id = "PROJ-2", kind = "blocking" },
  },
  tools = { { name = "approve_mr" } },
}
```

**Максимальный приоритет задачи** проекта ограничивает запрос; более высокий
приоритет — ошибка, а не тихое понижение.

### Удержания задач

Работа задачи может быть закончена, а результат ещё не проверен: CI пулл-реквеста
не зелёный, ревью никто не одобрил. Плагин удерживает задачу, пока не сможет
проверить результат:

```lua
cherrypi.hold_task(task_id, {
  key = "ci",
  reason = "CI is not green on pull request #12",
})

-- Позже, когда все проверки прошли:
cherrypi.release_task(task_id, "ci", {
  mode = "queue",
  prompt = "CI is green; finish the review.",
})
```

- Удерживаемая задача паркуется в `waiting`: она освобождает слот агента, и
  планировщик её никогда не берёт. Панель задачи показывает удержания рядом со
  ссылками и подзадачами, а причина ожидания называет плагин и причину.
- `key` — стабильное имя условия внутри плагина (`ci`, `approval`),
  `[a-z0-9_-]{1,32}`; повторное удержание того же ключа только обновляет
  причину. На одну задачу — не более 8 условий от одного плагина.
- Если запуск закончился, пока удержание есть, задача паркуется в `waiting` и
  агентство шлёт событие `task_held` вместо `task_settled`. `task_settled`
  по-прежнему значит, что задача действительно завершилась.
- Оператор может снять одно удержание из панели задачи (`ReleaseTaskHold`):
  лид или администратор выбирает режим, а удержание, которого уже нет,
  отклоняется вместо применения устаревшего режима.
- Каждое удержание, покинувшее задачу без снятия плагином, шлёт
  `task_hold_released` с `plugin`, `key`, `reason`, `mode`, `applied` и `cause`
  (`operator`, `closed_out`, `dequeued`, `archived` или `plugin_disabled`).
  `applied` равен false, если задачу всё ещё держит другое удержание или
  препятствие. Снятие по `plugin_disabled` доходит до выключаемого плагина до
  выгрузки его рантайма, хотя действовать с задачами он к тому моменту уже не
  может.
- Режим снятия применяется, только если это было последнее удержание, у задачи
  нет незавершённых блокеров или подзадач и её не удерживает другой плагин.
  `settle` (по умолчанию) завершает её, `queue` ставит в очередь с промптом,
  `complete` закрывает её. Если препятствие осталось, задача остаётся в
  `waiting`, а режим забывается. Если задача отклоняет режим, удержание
  возвращается и плагин получает ошибку: задача остаётся припаркованной, а не
  повисает без удержания.
- Ручное закрытие, `Dequeue` и `Archive` снимают все удержания, а явная
  постановка удерживаемой задачи в очередь отклоняется. Выключение или удаление
  плагина снимает его удержания с режимом `settle`, чтобы удержание без
  владельца не подвесило задачу.

### Host API

| API | Назначение |
| --- | --- |
| `cherrypi.log.info/warn/error(message, data)` | Структурные строки лога в панели плагина. |
| `cherrypi.json.encode/decode` | JSON-хелперы. |
| `cherrypi.settings.get(scope, target)` | Собственные настройки плагина для поверхности. `cherrypi.settings.<key>` читает org-значения. |
| `cherrypi.http.request(method, url, opts)` | Исходящий HTTPS, только по `network` (точные хосты, `*.`-поддомены или `*`). `opts`: `headers`, `body`, `timeout_ms`. |
| `cherrypi.db.query(sql, args)` / `cherrypi.db.exec(sql, args)` | Изолированная база плагина. |

| `cherrypi.actor` | Вызывающий: `kind`, `actor_id`, `username`, `admin`. |

### Инструменты задач

Инструмент из `tools` становится вызываемым, когда плагин прикрепляет его через
`create_task({ tools = { { name = "approve_mr" } } })`. Agency передаёт
определения агенту, тот регистрирует по одному Pi-инструменту на определение;
вызов возвращается в agency, которое проверяет, что задача принадлежит
вызывающему агенту, а инструмент прикреплён, и лишь затем вызывает
`handle_tool_call`.

Поскольку плагин хранит соответствие провайдера в своей базе, аргументы
инструмента не повторяют уже известный контекст — достаточно id задачи.

### Инструменты проекта

Инструмент из `project_tools` прикрепляется к **каждой** задаче, запущенной в
проекте, где включён плагин, а не только к задачам, которые создал плагин. Так
интеграция с провайдером предлагает инструмент для работы, которую проект уже
ведёт: например `open_merge_request`, который открывает пулл-реквест и
записывает, какой задаче он принадлежит, вместо ручных вызовов API агентом.

```json
"tools": [
  { "name": "open_merge_request", "description": "…", "input_schema": { … } }
],
"project_tools": ["open_merge_request"]
```

- Имена должны быть объявлены в `tools`; agency проверяет их при установке.
- Инструмент проекта действует, пока плагин включён в проекте, поэтому
  выключение плагина убирает его из новых запусков задач.
- Плагин, объявивший обработчик `task_tools`, сужает список для каждой задачи
  через `handle_task_tools(task_id)`; см.
  [Фильтр инструментов задачи](#фильтр-инструментов-задачи).
- `handle_tool_call(task_id, name, args)` получает задачу, из которой вызван
  инструмент, создал ли её плагин или нет.
- Инструмент задачи с тем же именем побеждает, потому что несёт контекст
  конкретной задачи.

## Данные, секреты и логи

- Каждый плагин получает изолированный SQLite-файл (или отдельную базу/схему
  PostgreSQL) и применяет свои `migrations/sqlite` или `migrations/pg` по
  порядку.
- Настройки хранятся по поверхностям; секретные значения не покидают agency.
- Каждый вызов и обращение к host API логируются; **Organization settings →
  Plugins → Logs** показывает последние строки.
- Бандлы проверяются до записи на диск: path traversal, слишком большие файлы,
  слишком много файлов, отсутствие манифеста или entry-файла отклоняются.

## Ограничения

- Сейчас доступен только Lua; JavaScript и WASM планируются за тем же
  контрактом обработчиков.
- Нет отдельного типа «внутренних проектов»: плагин работает в обычных
  проектах, где его актор — участник.
- Страницы и виджеты плагинов пока недоступны; `handle_http_request` — это
  единственная HTTP-поверхность.
- Настройки уровня команды зарезервированы на будущее.
