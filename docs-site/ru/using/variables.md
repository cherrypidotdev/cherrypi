# Переменные и секреты

**Переменная** — это значение окружения, которое получает оболочка задачи.
Определите его один раз на нужном уровне, и его получат все подходящие задачи —
без копирования ключа в промпт.

Переменная бывает **обычной** или **секретной**:

|  | Обычная | Секретная |
| --- | --- | --- |
| Видна в дашборде | Да | **Нет** — маска, только замена |
| Шифруется на диске | Нет | Да (`CHERRYPI_SECRET_KEY`) |
| Вырезается из вывода инструментов | Нет | Да, как `[secret:NAME]` |
| Попадает в оболочку задачи | Да | Да |

Доставка у обоих видов одна и та же; различается только видимость.

## Где можно определить переменную

| Уровень | Действует на | Кто управляет |
| --- | --- | --- |
| Организация | все задачи | администраторы |
| Проект | задачи проекта | владельцы проекта |
| Команда | задачи агентов, входящих в команду | владельцы команды |
| Группа агентов | задачи агентов-участников | владельцы группы |
| Агент | задачи агента | владельцы агента |

Уровень команды следует **собственному** членству агента — напрямую или через
его группы агентов, — а не командам, владеющим задачей: переменная описывает
машину и её учётные данные, поэтому следует за машиной. Родительские проекты не
передают переменные дочерним.

## Приоритет

Побеждает самый конкретный уровень:

```
агент > группа агентов > команда > проект > организация
```

Два одноуровневых источника (например, две команды) разрешаются детерминированно
по возрастанию id, а проигравшее определение показывается как **перекрытое** в
представлении _Действующие переменные_ у агента — перекрытие видно, а не
удивительно.

## Как добавить

1. Откройте вкладку **Переменные** нужного уровня: **Организация → Настройки →
   Переменные**, **Настройки → Переменные** проекта, **Переменные** команды,
   **Переменные** группы агентов или **Настройки → Переменные** агента.
2. Нажмите **Добавить переменную**, укажите имя (например, `ACME_TOKEN`),
   значение и необязательную заметку.
3. Включите **Хранить как секрет**, если значение не должно быть прочитано
   снова.

Заметка показывается модели рядом с именем; значение — нет.

### Имена

Имя должно быть переносимым именем переменной окружения:
`[A-Za-z_][A-Za-z0-9_]{0,127}`. Зарезервированы и отклоняются: `PATH`, `HOME`,
`USER`, `LOGNAME`, `SHELL`, `ENV`, `BASH_ENV`, `IFS`, `PWD`, `OLDPWD`,
`TMPDIR`, `NODE_OPTIONS`, `GIT_ASKPASS`, `SSH_AUTH_SOCK`, `SSH_ASKPASS`, а также
всё, что начинается с `CHERRYPI_`, `PI_`, `LD_` или `DYLD_`.

Значение — от 1 байта до 64 КиБ; допускаются переводы строк (PEM-ключ), но не
NUL.

## Как использовать в задаче

Оболочка задачи видит объединённый набор как обычные переменные окружения:

```sh
curl -H "Authorization: Bearer $ACME_TOKEN" https://api.acme.example/v1/items
```

Значение добавляется в окружение каждого **дочернего процесса bash**, но не в
окружение самого воркера, поэтому две задачи на одном агенте не видят значения
друг друга. Оно не попадает ни в рабочее пространство задачи, ни в сохранённый
диалог, а вхождения секрета вырезаются из вывода инструментов — `env` напечатает
`ACME_TOKEN=[secret:ACME_TOKEN]` вместо значения.

Ротация доходит до следующей команды: воркер перепроверяет набор при каждом
старте запуска и читает его при каждом вызове оболочки, поэтому новое или
заменённое значение доступно без перезапуска. _Список_ имён в системном промпте
строится один раз за сессию, поэтому новая переменная появится в промпте со
следующей свежей сессии; оболочке значение доступно уже раньше.

## Превращение обычной переменной в секрет

**Сделать секретом** шифрует текущее значение и скрывает его навсегда. Обратная
операция намеренно недоступна: раскрытие сохранённого секрета нарушило бы
обещание, что никакой API его не возвращает. Удалите переменную и добавьте новую
обычную.

## Требования и ограничения

Секретам нужен `CHERRYPI_SECRET_KEY` (см.
[Переменные agency](/ru/reference/environment#секреты-провайдеров)). Без него
обычные переменные продолжают работать, а дашборд объясняет, почему секреты
недоступны.

Функция не пускает значение в диалог, рабочее пространство, запрос к провайдеру
модели и дашборд. Она не защищает значение от владельца агента (он контролирует
машину), от модели, которой значение намеренно передали, и от оператора,
имеющего и базу данных, и `CHERRYPI_SECRET_KEY`.
