# Настройка агента

Агент читает флаги, переменные окружения и необязательный `.env` в рабочем
каталоге (загружается автоматически). Флаги важнее окружения.

## Флаги

| Флаг | Переопределяет | Значение |
| --- | --- | --- |
| `--agency-url` | `CHERRYPI_AGENCY_URL` | URL agency для туннеля. Обязателен. |
| `--token` | `CHERRYPI_AGENT_TOKEN` | Personal access token (`pat_…`). |
| `--display` | `DISPLAY` | X-дисплей для моста рабочего стола. |
| `--xauthority` | `XAUTHORITY` | X authority для `--display`. |

## Переменные окружения

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `CHERRYPI_AGENCY_URL` | — | URL agency (обязателен). |
| `CHERRYPI_AGENT_TOKEN` | — | Personal access token (`pat_…`). `--token` важнее; токен важнее кэшированного файла. |
| `CHERRYPI_DIR` | `~/.cherrypi` | Каталог данных: SQLite, токен, рабочие пространства задач. |
| `CHERRYPI_DATABASE_DSN` | `$CHERRYPI_DIR/cherrypi.sqlite3` | Локальная база агента. |
| `CHERRYPI_AGENT_TUNNEL_TRANSPORT` | `auto` | `auto`, `http2` или `websocket`. Только диагностика. |
| `CHERRYPI_LOG_FORMAT` | `text` | `text` или `json`, по строке на запись. |
| `CHERRYPI_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error`. |
| `CHERRYPI_LOG_FILE` | `$CHERRYPI_DIR/logs/agent.log` | Долговечная копия лога; пусто отключает. |
| `CHERRYPI_LOG_FILE_MAX_MB` | `8` | Размер, после которого файл ротируется. |
| `CHERRYPI_LOG_FILES` | `3` | Сколько ротированных файлов хранить (`agent.log.1` …). |
| `DISPLAY` | — | X-дисплей для рабочего стола. |
| `XAUTHORITY` | — | X authority. |
| `SHELL_BIN` | `$SHELL`, затем `/bin/bash` | Shell для root-терминалов. |

## Токены

Personal access token — единственный креденшел агента. Источников два, в
порядке приоритета:

1. **`--token` / `CHERRYPI_AGENT_TOKEN`** — явный токен. Он фиксирован:
   ротация файла токена его не переопределяет. Для нового токена перезапустите
   агента.

Username/password fallback нет. Если оба источника пусты, агент завершается с
инструкцией.

Считайте каталог данных секретом: кэшированный токен даёт доступ агента.

## Каталог данных

```text
$CHERRYPI_DIR/
  cherrypi.sqlite3        # локальный кэш задач/использования
  sessions/<task id>/     # рабочие пространства задач и вложения
```

Рабочие пространства могут разрастаться. Держите `CHERRYPI_DIR` на диске с
местом под репозитории, зависимости и build-выход. Agency хранит историю сессии
Pi, поэтому workspace можно пересоздать повторным запуском задачи; но
незакоммиченные файлы, не прикреплённые и не опубликованные как артефакты,
пропадут при удалении каталога.

## Конфигурация моделей

Агент сам модели не настраивает. Администратор объявляет провайдеров и модели в
**Settings → Models** в agency; agency зашифровывает ключ каждого провайдера и
проксирует все запросы, поэтому у воркера нет ни одного креденшела, а объявленные
модели (с учётом грантов) — единственные, которые может выбрать задача. Агент
без объявленных моделей ничего не предлагает, и его задачи падают с ошибкой «no
models are available».

**OAuth-логины не поддерживаются.** Agency хранит по API-ключу на провайдера и
не реализует OAuth, поэтому подписки Claude Pro/Max, Codex и Copilot
использовать нельзя. Настройте API-ключ на странице провайдера.

Изменённый каталог доходит до работающего агента:

- **Reset models** в **Agents → Tasks**, рядом с моделью по умолчанию, заново
  читает каталог и показывает его в этом списке (композер задачи подхватит его
  при следующем открытии).
- **Restart Pi session** в панели деталей задачи останавливает тёплый рантайм
  этой задачи, поэтому следующий запуск читает каталог заново. Кнопка недоступна,
  пока идёт запуск или анкета ждёт ответа: перезапуск потерял бы эту работу.

## MCP-серверы

MCP-серверы приходят из двух мест и объединяются по имени:

- **библиотека MCP и навыков агентства**, установленная для организации,
  проекта, команды, группы агентов или этого агента и передаваемая в пакете
  конфигурации, который получает задача. Это **HTTP-эндпоинты, к которым
  обращается само агентство**: воркер получает путь прокси
  (`/api/rest/agent-mcp/<name>`), а не адрес сервера, а агентство подставляет
  запечатанные заголовки записи — поэтому эта машина не хранит ни адрес, ни
  учётные данные;
- файл `~/.agents/mcp-settings.json` на хосте — соглашение AGENTS
  (`mcpServers`, тот же формат, что читают `pi-mcp-adapter` и [CC]). Он может
  объявлять stdio-серверы (`command`/`args`/`env`) и HTTP-серверы
  (`url`/`headers`), и воркер подключается к ним напрямую.

Определение агентства выигрывает при совпадении имени, а выключенная запись
агентства скрывает одноимённый элемент хоста. Запись **хоста** задаёт
`command`/`args`/`env` (stdio) либо `url`/`headers` (HTTP), а также `disabled`,
`description`, `connectTimeoutMs` (по умолчанию 15 с), `requestTimeoutMs`
(15 мин), шаблоны `includeTools`/`excludeTools` и `directTools` (`true`,
`false` или список имён). Для сервера хоста `${VAR}` и `${VAR:-default}`
раскрываются из окружения воркера, а сервер с неразрешённой ссылкой
пропускается и попадает в отчёт; у записи агентства значений здесь нет —
агентство уже подставило их в запрос.

Серверы подключаются при старте рантайма задачи и закрываются вместе с ним.
Сбой сервера — это строка в журнале и строка на вкладке **Система** задачи, а не
сбой задачи; его инструменты доступны модели как `mcp__<server>__<tool>`.

## Логи

Логи идут в stdout, а зеркало не-локальных записей отправляется в agency для
вкладки **Logs** на странице агента.

```sh
CHERRYPI_LOG_FORMAT=json
CHERRYPI_LOG_LEVEL=debug
```

Stderr самого Pi остаётся локальным и попадает в agency как вывод консоли
задачи.

## Лимиты параллельности

Сколько задач может выполнять агент, решает agency, а не агент. В
**Agents → Limits** задаются:

- общий лимит параллельных задач;
- лимит на проект;
- лимиты по тегам и тегам внутри проекта.

Значения по умолчанию намеренно консервативны (`1` всего, `1` на проект).
Повышайте их, только если у машины есть CPU, RAM и запас по лимитам провайдера.

## Транспорт туннеля

В обычном развёртывании `CHERRYPI_AGENT_TUNNEL_TRANSPORT` не задавайте. `auto`
пробует HTTP/2 и откатывается на WebSocket поверх HTTP/1.1. Явные значения
(`http2`, `websocket`) — диагностика.

Если reverse proxy ломает туннель, не форсируйте h2c перед agency; настройте
прокси на WebSocket и отключите read timeout.

## Рабочий стол

Задайте `DISPLAY` (и обычно `XAUTHORITY`), чтобы показать существующую X-сессию.
Без них рабочий стол отключён. См.
[Доступ к рабочему столу](/ru/agent/desktop).
